# Open-repository release plan

This plan follows the 9 November review. It does not authorize new metric experiments, shared-history rewriting, new paid services, a default-branch change or a conference submission.

1. **Make the landing page accurate (OR-02, OR-06).** Describe the current contribution as a reference/control audit for inpainting and conditional generation. Label model assumptions, real-data provisional states, withdrawn results and the unrun generator/subgroup endpoint. Link the canonical paper, evidence freeze, current exports and review records. Acceptance: a reader can identify the active branch, current/frozen evidence and supported claims without opening a handoff log.
2. **Resolve publication scope (OR-01, OR-11).** List every public figure/array family as synthetic, template, aggregate mean/map, statistic or individual example. Record source dataset/version, original terms, project licence, publishing basis, citation and rights-review status. Reconcile the real-QTIM exception with the no-real-images policy. Acceptance: no asset receives a licence broader than the publishing basis that has been established; restricted images/IDs remain external.
3. **Provide installable environments (OR-03, OR-04).** Separate core/offline checks, paper build and optional MRI/face/iris/fundus tools. Pin Python and dependencies, model revisions/checksums and caches. Mark model-download integration tests and state their cost/size/network requirements. Acceptance: a fresh documented Python 3.11 environment runs the offline suite and aggregate paper build; optional integration runs are explicit. Do not weaken frozen guards for a green badge.
4. **Apply English consistently (OR-05).** Translate current public prose and generator strings together. Mark immutable historical/quoted exceptions. Acceptance: regeneration preserves the English active reports and captions; historical evidence is not silently rewritten.
5. **Prepare a maintainable release (OR-07 to OR-10, OR-12).** Add strict, versioned JSON exports with null plus explicit missingness; retain raw historical bytes. Add CI, citation/contribution/security documents and scoped secret/data/model ignore rules. State branch/tag purposes and raw versus normalized hash conventions. Acceptance: an automated outgoing-artifact check catches prohibited paths, unresolved language requirements and schema defects; dataset rights and GitHub security settings have named author decisions.

The newer P3/brain/face/IXI results should be reviewed for the next synchronized paper/results release. This does not require inventing a winning metric or launching the proposed generator experiment. The current frozen paper can remain separately labelled and reproducible from its saved sources.
